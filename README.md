# 聚合搜索 · 静态版

纯静态网页，无服务端程序、无数据库、无边缘计算。数据来自同目录下的两个 CSV 文件，改表后按 F5 即可更新。

## 文件结构

```
newwan/
├── index.html          页面骨架（固定，无需改动）
├── assets/
│   ├── style.css       页面样式（固定，无需改动）
│   └── app.js          逻辑脚本（固定，无需改动）
├── 关键词表.csv         人物数据 ← 日常维护改这个
└── 搜索引擎表.csv       搜索引擎数据 ← 日常维护改这个
```

## 日常维护三步

1. 本地编辑 CSV（**务必保存为 UTF-8 编码**）
2. 覆盖服务器上的同名文件
3. 浏览器按 **F5** 刷新 → 新数据即刻生效

> index.html / style.css / app.js 永远不用动，页面会自动使用 CSV 里的全部数据。

## 关键词表.csv（人物表）

| 表头 | 必填 | 说明 |
|------|------|------|
| 艺人名字 | 是 | 空行自动跳过；重名自动去重 |
| 头像图片链接 | 否 | 公开可访问的图片 URL；加载失败显示名字首字 |
| 地区 | 否 | 用于筛选，选项自动生成 |
| 体型 | 否 | 用于筛选，选项自动生成 |
| ins / 推特 / P站 / … | 否 | 社交主页链接；**列名可随意增删改**，列名即按钮文字 |
| 作品1～作品N | 否 | 格式 `名称\|链接`；按表头含"作品"识别，不限于 5 列 |

示例行：

```text
李冰冰,https://xxx.jpg,中国,高,https://instagram.com/xxx,https://x.com/xxx,,,保持|https://example.com/work1,未来|https://example.com/work2
```

## 搜索引擎表.csv（引擎表）

| 表头 | 必填 | 说明 |
|------|------|------|
| 站点名称 | 是 | 按钮上显示的文字 |
| 搜索地址 | 是 | 关键词位置写成 `{q}`，打开时自动替换为人物名字（URL 编码） |

示例行：

```text
百度,https://www.baidu.com/s?wd={q}
```

新增一行即新增一个按钮，按钮会自动变窄平铺，不会出现横向滚动条。

## 红线（改动会失效）

- **文件名和位置别动**：必须叫 `关键词表.csv`、`搜索引擎表.csv`，且与 index.html 同一文件夹
- **表头关键字段别改名**：`艺人名字`、`头像图片链接`、`地区`、`体型`、`作品N`、`站点名称`、`搜索地址`
- **编码保持 UTF-8**：用记事本/VSCode/Excel"另存为 CSV UTF-8"均可；存成 GBK 也不会乱码（已做自动兼容），但建议统一 UTF-8

## 部署与访问

把整个 newwan 文件夹放到任意静态服务器即可：IIS、nginx、宝塔、GitHub Pages、Vercel、Netlify，或临时预览用 `python -m http.server 8080`。

注意：直接双击 index.html（file:// 方式）浏览器会禁止读取本地 CSV，页面会提示错误——必须通过 http:// 访问。

## 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 顶部出现黄色警告条 | 按提示检查 CSV 是否在同一目录、文件名是否正确，改完按 F5 |
| 人物没显示 | 检查"艺人名字"列是否有值；表头是否被改过名 |
| 名字或站点名乱码 | CSV 编码问题，另存为 UTF-8 后重新上传 |
| 加了新引擎没出现 | 检查"搜索地址"是否为完整 http/https 链接且含 `{q}` |

## 访问本地预览
现在访问的`http://127.0.0.1:8899` 是我之前验证时在你电脑上临时起的 Python 静态服务 （就是把 newwan 文件夹对外递文件），它只是本地预览用， 不是这个网页的依赖 。

- 本地临时预览 ：如果那个服务停了，在 newwan 目录跑一句`python -m http.server 8899` 即可恢复；用 VS Code 的 Live Server 插件也等价
- 正式使用 ：把 newwan 文件夹整体扔到你的静态服务器（你是网管，IIS 加个站点或 nginx 加个 location 都是一分钟的事），之后本地这个 8899 就不需要了
